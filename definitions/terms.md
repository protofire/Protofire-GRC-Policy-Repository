# Term Definitions

> Source: Consolidated from all L0–L2 documents
> Last-Updated: 2026-04-08
> Canonical: true

| ID | Term | Definition | Source |
|---|---|---|---|
| DEF-001 | Node | Financially independent delivery unit within Protofire. Operates one or more engagements under Track A and/or Track B. | L0-4 §2 |
| DEF-002 | Engagement | A project delivery instance classified as Track A (internal) or Track B (client). | L0-4 §2 |
| DEF-003 | Track A | Internal incubation track. Protofire owns product risk. | L2-DEL-101 §2 |
| DEF-004 | Track B | Customer engagement track. Client owns product risk. Requires client signatures for waivers. | L2-DEL-101 §2 |
| DEF-005 | Gate | Mandatory decision checkpoint in the delivery lifecycle. Requires designated signers, evidence, and Hard Stop checks. | L2-DEL-101, CL-PHASE-001 |
| DEF-006 | Hard Stop | An absolute blocking condition that halts project progression. Seven defined: HS-01 through HS-07. | L0-1 §7.3, L1-ERM-001 §7.2 |
| DEF-007 | Composite Risk Score | Weighted combination of C (Client), B (Business), P (Project) pillar scores. Range 1.0–4.0. | OPS-001 §3 |
| DEF-008 | Risk Tier | Classification derived from Composite Risk Score: T1 (1.0–2.9), T2 (3.0–3.5), T3 (3.6–4.0), T4 (Enterprise escalated). | L1-ERM-001 §5 |
| DEF-009 | C/B/P Model | Three-pillar risk scoring: Client risk (C1–C3), Business risk (B1–B3), Project risk (P1–P3). | OPS-001 §3 |
| DEF-010 | SoD | Separation of Duties. No role may approve a control for which they are also the Responsible party. | POL-004 §2.4 |
| DEF-011 | Two-Person Rule | Requirement that deployer and reviewer/approver must be distinct individuals at testnet and mainnet deployment. | POL-002 §3.5 |
| DEF-012 | MSA | Master Services Agreement. Legally binding engagement contract. HS-02 trigger if absent. | L1-ENG-002 §5 |
| DEF-013 | TVL | Total Value Locked. On-chain metric measuring assets under protocol control. HS-03 trigger if > $1M without audit. | L2-ASSURE-103 §2 |
| DEF-014 | PSF | Project Security Framework. Engagement-specific security plan initiated at kickoff. | CL-PHASE-001 Phase 4 |
| DEF-015 | RACI-001 | Consolidated Responsibility Assignment Matrix with named individuals per engagement. | GRC-PF-001 |
| DEF-016 | KRI | Key Risk Indicator. Measurable metric with RAG thresholds used for continuous monitoring. | POL-010 §3, L0-2 §8.2 |
| DEF-017 | Exception | Formal deviation from a policy requirement, classified E1–E4 with defined approval authority and duration. | POL-009 §2 |
| DEF-018 | ROPA | Record of Processing Activities per GDPR Art.30. Maintained by DPO. | POL-011 §12, REG-505 |
| DEF-019 | DPIA | Data Protection Impact Assessment per GDPR Art.35. Mandatory for T2+ engagements processing EU personal data. | POL-011 §6 |
| DEF-020 | DSR | Data Subject Request per GDPR Art.12–23. Acknowledged within 3 business days; fulfilled within 30 calendar days. | POL-011 §7 |
| DEF-021 | Gordon-Loeb Model | Economic model capping optimal security investment at 37% of expected loss. Used for budget floors. | L0-1 §7.2 |
| DEF-022 | RAG | Red/Amber/Green status classification. Applied to KRIs, risk scores, and gate readiness. | OPS-001, POL-010 |
| DEF-023 | Irreversibility Gate | Final pre-deployment gate (G7). Once passed, on-chain actions may be irreversible. Requires NO + CISO + TL. | CL-PHASE-001 Phase 9, L2-DEL-101 |
| DEF-024 | Signing Ceremony | Formal key generation/transfer event for multisig wallets. Documented per CL-411. | L1-KEY-005, CL-411 |
| DEF-025 | ISMS | Information Security Management System per ISO/IEC 27001:2022. Scope defined in L0-4. | L0-4 |
| DEF-026 | Change Classification | 5-class model (C1–C5) for categorizing changes by risk and approval requirements. | POL-005 §2 |
| DEF-027 | Evidence Calendar | 23 recurring GRC activities mapped to month-by-month schedule with owners and evidence types. | GRC-MASTER-001 Part III |
| DEF-028 | SoA | Statement of Applicability per ISO 27001 Cl.6.1.3. Documents applicable Annex A controls. | ISO 27001:2022 |
